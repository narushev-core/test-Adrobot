## Функциональные требования

Описал базово, не стал упоминать нагрузку и т.д

### 1. Создание кампании

| ID | Требование |
|----|------------|
| FR-1 | Форма создания принимает название кампании, гео-код страны и ID оффера Keitaro. |
| FR-2 | По введённым данным через Keitaro API создаётся кампания. |
| FR-3 | У созданной кампании настроены домен, группа и источник трафика. |
| FR-4 | В кампании создаётся поток 1: ловит всех пользователей из указанной страны и редиректит на Google. |
| FR-5 | В кампании создаётся поток 2: редиректит на выбранный оффер. |

### 2. Редактор кампании

| ID | Требование |
|----|------------|
| FR-6 | Можно выбрать и открыть существующую кампанию. |
| FR-7 | В кампанию можно добавить оффер. |
| FR-8 | Из кампании можно удалить оффер. |
| FR-9 | Логика редактора повторяет существующий редактор из видео: все кнопки работают, отображаемые цифры верные. |

## Нефункциональные требования

### Из ТЗ

| ID | Требование |
|----|------------|
| NFR-1 | Бэкенд написан на FastAPI + SQLAlchemy. |
| NFR-2 | Фронтенд — на выбор разработчика. |
| NFR-3 | Код сдаётся ссылкой на GitHub-репозиторий. |
| NFR-4 | В README описаны применение миграций и запуск проекта. |

### Дополнительные

| ID | Требование |
|----|------------|
| NFR-5 | API-ключ Keitaro хранится только на бэкенде в переменных окружения. В репозитории лежит `.env.example`, а реальный `.env` не коммитится. Фронтенд не обращается к Keitaro напрямую. |
| NFR-6 | Миграции БД выполняются через Alembic. |
| NFR-7 | Проект запускается одной командой через `docker compose up`. |
| NFR-8 | Входные данные валидируются: гео-код в формате ISO 3166-1 alpha-2, ID оффера существует в Keitaro, название непустое. При ошибке пользователь видит понятное сообщение. |
| NFR-9 | Если создание кампании падает на середине (кампания создана, а поток — нет), уже созданные сущности удаляются, чтобы в Keitaro не оставалось недоделанных кампаний. |
| NFR-10 | Ошибки Keitaro API (недоступность, неверный ключ, некорректный запрос) обрабатываются и возвращаются пользователю в понятном виде, а не как необработанная 500-я ошибка. |
| NFR-11 | На все запросы к Keitaro установлены таймауты. |
| NFR-12 | Ключевая логика (создание кампании, добавление и удаление офферов) покрыта тестами с моками Keitaro API. |
| NFR-13 | Запросы к Keitaro и ошибки логируются, API-ключ в логи не попадает. |
| NFR-14 | Документация API доступна через встроенный в FastAPI Swagger (`/docs`). |
